### [AugBridge Commerce — Order Fulfillment & Exception Monitoring](https://github.com/huongpham4869/augbridge-commerce-ba-case-study)

*Independent Portfolio Project · E-commerce operations*

- **Problem:** A small Etsy business with 6 shops and 3 suppliers handles every order by hand: choosing the supplier, entering the order, checking its status and copying tracking to Etsy. In peak season, late orders are found too late.
- **Evidence:** SQL analysis of 10,685 simulated orders: 81.0–83.7% of orders are overdue in peak weeks, compared with 5.2–7.1% in normal weeks. This is used as context only, because the data cannot show what causes the delays.
- **Proposal:** One shared Lark workspace with Product Type → supplier mapping, supplier API integration and an exception queue, chosen by scoring five options. A pilot plan measures manual time per order against a 6.0-minute planning benchmark.
- **Artifacts:** BRD · FRD · 16 user stories · 34 UAT test cases (not run) · RTM · SQL

### [HealthFirst Care — Hospital Operations Improvement](https://github.com/huongpham4869/healthfirst-care-ba-case-study)

*Capstone Project · Healthcare operations*

- **Problem:** A hospital with five clinical departments relies on separate systems and manual hand-offs for appointments, resources and reporting.
- **Evidence:** Excel analysis of sample data: 60% of appointments disrupted (12 of 20, including rescheduled), a 20% no-show rate and an average satisfaction score of 7.0 / 10. Waiting time cannot be measured from the data.
- **Proposal:** To-Be processes in BPMN for scheduling, check-in and coordination between departments, and 26 requirements traced in an RTM. This includes the timestamps needed before the case brief's 20% waiting-time target can be tested.
- **Artifacts:** BRD · RTM · stakeholder analysis · BPMN models · data analysis and dashboard · risk management plan
